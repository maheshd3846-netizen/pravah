# PRAVAH Phase 3B Implementation Report

## 1. Implementation Summary

Phase 3B establishes the closed-loop evaluation mechanism for PRAVAH. Building upon Phase 3A's MILP mathematical optimization engine and Phase 1's discrete-event simulation foundation, Phase 3B answers the fundamental question:
> **Does the logistics plan generated by the optimizer actually improve the simulated outcome when injected into the same disrupted environment?**

By pairing two independent simulations from an identical initial state snapshot (verified via SHA-256 fingerprinting), Phase 3B measures true counterfactual deltas across inventory, service fulfillment, stockout duration, convoy transit delay, transport distances, and fleet utilization.

All results are calculated from actual physical simulation trajectories; no hard-coded or fabricated improvement figures are used anywhere in the system.

---

## 2. State Snapshot Architecture

Implemented in [`simulation/state_snapshot.py`](file:///c:/Users/HP/Desktop/Pravah/simulation/state_snapshot.py):
- **`StateSnapshot`**: Immutable, serializable dataclass capturing:
  - World node attributes and inventory allocations.
  - Route statuses, dynamic capacities, and distances.
  - Vehicle statuses, payload limits, and current locations.
  - In-flight shipments and active environmental disruptions.
  - Random seed, current simulation hour, and scenario identifiers.
- **Deterministic Hashing**: The `hash()` method generates a SHA-256 digest over normalized, sorted JSON structures.
- **Isolated Cloning & Restoration**: `clone()` returns a deep copy, while `restore_into(simulator)` loads the snapshot state into a fresh simulator instance without mutable reference leaks or pointer aliasing.
- **Integrity Guard**: If $\text{hash}(\text{baseline}) \ne \text{hash}(\text{intervention})$, the evaluator rejects the experiment as `INVALID`.

## 3. Baseline / Intervention Methodology

1. **Strictly Paired Design**:
   - Both baseline and intervention runs run with identical random seeds and common random numbers (CRN).
   - Both runs encounter the exact same weather shocks, road degradations, and demand variations at the identical hours.
2. **Baseline Run**:
   - Executes standard status-quo operations with no optimizer intervention.
   - Serves as the uncorrupted counterfactual control.
3. **Intervention Run**:
   - Starts from the restored snapshot.
   - Recommended dispatch decisions are converted into discrete `Shipment` entities.
   - Source inventory is immediately deducted at dispatch.
   - Shipments travel along designated routes respecting terrain and dynamic weather delays.
   - Inventory arrives and is credited at the destination strictly at `actual_arrival`.

## 4. Evaluation Metrics

Aggregated in [`optimization/evaluation_metrics.py`](file:///c:/Users/HP/Desktop/Pravah/optimization/evaluation_metrics.py) through `SimulationRunMetrics`:
- **Inventory**: Starting inventory, ending inventory, minimum aggregate stock level, and hourly average inventory.
- **Service**: Total requested demand, total fulfilled demand, unmet demand, and fulfillment percentage ($\frac{\text{fulfilled}}{\text{requested}} \times 100\%$).
- **Stockouts**: Total stockout events, cumulative stockout hours, affected nodes count, and affected items count.
- **Safety Stock**: Safety stock breach incidents and breach duration.
- **Transport & Delays**: Total kilometers traveled, total transit hours, average convoy delay, and maximum single-shipment delay.
- **Fleet**: Fleet utilization rate ($\frac{\text{busy}}{\text{total}}$) and active vehicle count.
- **Critical Nodes**: Per-node breakdown of earliest stockout hour, stockout occurrence boolean, and survival extension hours.

## 5. Delta Methodology

Calculated via `MetricDelta`:
- $\text{absolute\_delta} = \text{optimized} - \text{baseline}$
- $\text{relative\_delta\_percent} = \frac{\text{absolute\_delta}}{|\text{baseline}|} \times 100\%$
- Qualitative direction classification:
  - `lower_is_better = True`: Unmet demand, stockout events, stockout hours, delays, transport distance.
  - `lower_is_better = False`: Fulfillment percentage, survival hours.
  - Threshold guard: Differences below $10^{-3}$ absolute or $0.1\%$ relative are marked `UNCHANGED`.

### Verdict Classification Rules
- `INVALID`: Constraint violations or snapshot hash mismatch.
- `IMPROVED`: Service improved with no increase in transport distance.
- `MIXED`: Service improved, but required increased transport distance/convoys.
- `DEGRADED`: Service worsened compared to baseline.
- `INCONCLUSIVE`: Negligible changes across all metrics.

## 6. Plan Validation

Implemented in [`optimization/plan_adapter.py`](file:///c:/Users/HP/Desktop/Pravah/optimization/plan_adapter.py) through `OptimizationPlanAdapter.validate_plan`:
- Pre-execution validation verifies:
  1. Source node inventory sufficiency for planned dispatches.
  2. Route existence, blockage status (`BLOCKED`), and dynamic throughput capacity.
  3. Vehicle availability (`AVAILABLE`) and payload capacity compliance.
- Invalid plans are rejected upfront with `status = "PLAN_INVALID"` and explicit diagnostic violations, preventing non-physical simulations.

## 7. Shipment Trace

Each optimizer decision is traced end-to-end via `ShipmentExecutionTrace`:
- `decision_id`, `item`, `planned_quantity`, `actual_dispatched_quantity`, `actual_arrival_quantity`.
- `source_node`, `destination_node`, `route_id`, `vehicle_id`.
- `departure_hour`, `arrival_hour`, `transit_delay_hours`.
- `status`: `DELIVERED`, `IN_TRANSIT`, or `FAILED` (with recorded `failure_reason`).

## 10. Demo Results (`scripts/run_counterfactual_demo.py`)

Run under `COMPOUND_DISRUPTION` with $72\text{h}$ horizon and P80 demand policy:
- **Baseline Simulation**:
  - Unmet Demand: $4,172.2\text{ units}$
  - Stockout Events: $56\text{ events}$ ($56\text{h}$ total)
  - Fulfillment Rate: $96.76\%$
- **Optimized Intervention Simulation**:
  - Unmet Demand: $1,132.4\text{ units}$
  - Stockout Events: $21\text{ events}$ ($21\text{h}$ total)
  - Fulfillment Rate: $99.12\%$
- **Counterfactual Deltas**:
  - Unmet Demand: $-3,039.8\text{ units}$ ($-72.86\%$) [`IMPROVED`]
  - Stockout Events: $-35\text{ events}$ ($-62.50\%$) [`IMPROVED`]
  - Fulfillment Rate: $+2.36\%\text{ points}$ [`IMPROVED`]
  - Delay: $+1.61\text{h}$ avg [`DEGRADED`] (due to high-altitude pass transit)
- **Tradeoff Summary**:
  - Transport Distance: $+1,653.7\text{ km}$ ($+169.3\%$) [`INCREASED`]
  - Risk: `MITIGATED`
  - Service: `IMPROVED`
- **Verdict**: `MIXED` (Service and risk improved at the expense of convoy deployment distance).

## 12. Known Limitations

1. **Non-Splittable Convoy Delays**: When a route degrades mid-transit, current logic extends total travel time uniformly rather than routing vehicles to immediate safe sidings.
2. **Single-Leg Shipments**: Current intervention injection models direct single-leg movements ($A \to B$); multi-hop transfers currently rely on regional hub staging.
